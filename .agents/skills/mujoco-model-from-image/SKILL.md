# 图片 → MuJoCo 模型

把一张设备/机器人图片，转成「结构先确认、再落地」的 MJCF 模型。

## 何时使用

- 使用：用户给了图片（照片、CAD 截图、专利图、草图），要求做 MuJoCo / 仿真模型。
- 使用：用户说「照这个机器人建个模型」「把它做成能仿真的 XML」。
- 不使用：用户只有文字描述、没有任何参考图 → 先索要图片，不要凭空建模。
- 不使用：用户只要 2D 示意图或设计讨论，不出 XML。

## 两条铁律

1. **没有参考图片就不建模。** 没图、没尺寸、没有实物参数时，停下来要图，并说清需要什么视角。不得凭常识编一个「差不多的机器人」。
2. **必须先出简化结构图，等用户明确确认后才写 XML。**「还行」「差不多了」不算确认，要追问到明确表态。

## 步骤

### 1. 收图并锁定需求

用 `read_image` 看图，确认三件事：

- 图片可读、主体完整（不是缩略图、关键部位没被裁掉）。
- 产出范围：只要机器人本体，还是要连地面/灯光/相机的场景。
- 尺寸依据：有实测尺寸吗？没有就说明将按图比例归一化。

完成信号：手里有一张能看懂的图 + 明确的产出范围。
图不可读或主体被裁 → 停止，请用户补图。

### 2. 读图，填信息表

逐项提取，提取不到的写「未定」：

| 项 | 从图里要看出来 |
| --- | --- |
| 拓扑 | 几个连杆、谁接谁、几条腿/臂 |
| 关节 | 每个关节在哪、绕哪根轴、什么类型 |
| 自由度 | 需要驱动的关节总数 |
| 比例 | 各段长度相对关系、宽高比 |
| 接触 | 足/轮/底盘的形状与落点 |
| 对称 | 是否左右镜像 |

完成信号：信息表填满，所有「未定」项进入下一步的假设清单。

### 3. 出简化结构图（在这里停）

按 `references/structure-diagram.md` 的固定格式输出五部分：层次树、示意图、连杆尺寸表、关节表、假设与待确认清单。

然后**只问一件事**：这个结构对不对？并把所有「待确认」项点名（比例、自由度、尺寸来源）。

完成信号：用户明确表示结构正确、可以开始建模。
用户提出修改 → 回到本步重出结构图，直到确认。

### 4. 生成 MJCF

按 `references/mjcf-conventions.md` 的规范写，骨架直接复制 `assets/model.template.xml` 再改。

- 几何只用 primitive（box / cylinder / capsule / sphere），不引入 mesh 文件。
- 默认输出两个文件：`<name>.xml`（机器人本体）+ `scene.xml`（`<include>` 本体，外加地面、灯光、相机）。
- 坐标轴、关节命名、碰撞掩码、关键帧全部照 conventions 走，不要临时发挥。
- 若当前仓库已有参数化生成器（例如 `desktop_robot/config.py`），优先复用它的坐标与关节约定，保证新旧模型一致。

完成信号：文件写完，`references/mjcf-conventions.md` 末尾的自检清单逐项通过。

## 失败处理

| 症状 | 判定 | 动作 |
| --- | --- | --- |
| 用户没给图 | 缺前置条件 | 停止建模，说明需要正视图/侧视图或标注尺寸的图 |
| 图糊、看不清关节 | 信息不足 | 列出看不清的具体部位，请用户补图或文字说明，不要猜 |
| 用户不给尺寸 | 可用比例法 | 在结构图里写明「假设总高 X m，其余按图比例缩放」；X 按用途取：桌面级 0.3 m、服务机器人 1.0 m |
| 用户对结构图回复含糊 | 未确认 | 把待确认项再列一遍，请其逐条答复，不要往下走 |
| MuJoCo 打不开 XML | 结构错误 | 常见三类：include 重复了 `<compiler>`、关节缺 `range`、关键帧 qpos 长度 ≠ nq；查 conventions 自检清单 |

## 验证

默认按静态自检走（conventions 末尾清单）。用户环境有 MuJoCo 时再补一条动态检查：

```bash
python -c "import mujoco; m = mujoco.MjModel.from_xml_path('scene.xml'); print(m.nq, m.nv, m.nu)"
```

打印出数字且不报错即为加载成功；再用 `mujoco.viewer` 看一眼姿态是否和结构图一致。
